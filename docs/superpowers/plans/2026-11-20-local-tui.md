# Local TUI implementation plan

**Goal** Provide `npm run tui` for manual local Docker lifecycle management.

**Spec** ../specs/2026-11-20-local-tui-design.md, approved by user.

**Architecture** Node TypeScript terminal menu delegates to a Docker Compose controller. Local override sets restart policies to no. Closing the menu preserves running containers and volumes. Only explicit Start launches services. Configuration is prepared only on explicit Start.

## Contracts and ownership

- Controller owns src/local/controller.ts, docker-compose.local.yml and tests/local-controller.test.ts. Export LocalController with async status(), start(), stop(), openDashboard(), logs(), prepare(). Constructor accepts optional projectRoot. status returns {state: "running"|"stopped"|"partial"|"unavailable", message: string, url: string}. Methods return Promise<void>, errors have user-readable messages. logs streams until Ctrl+C, returning to menu.
- Menu owns src/cli/local-tui.ts and tests/local-tui.test.ts. It imports LocalController from ../local/controller.js and offers explicit start/open/logs/stop/exit. Non-TTY produces clear guidance. Root adds npm script and docs.
- Root integrates, verifies real temporary Docker lifecycle and performs independent review.

## Tasks

- [ ] Write targeted regressions before implementing controller configuration, command construction, errors, stopped/running state and persistent shutdown semantics.
- [ ] Implement private first-run .env configuration with random password, preserve existing files, use uid/gid, container-relative session paths, disabled restart policies and bounded readiness polling.
- [ ] Write terminal menu regressions, implement keyboard actions and graceful Ctrl+C without stopping containers. Logs Ctrl+C terminates only log follower.
- [ ] Add npm run tui, document prerequisites and commands, run typecheck/build/full tests and Compose validation.
- [ ] Exercise real start/readiness/exit/reopen/stop using a disposable project and verify volumes persist and restart policy is no.

## Constraints

Preserve existing uncommitted feature work and sessions. Do not install startup services. Do not enable arbitrary existing Compose projects or remove volumes. Avoid shell interpolation for subprocess arguments. Configuration/setup occurs only when user chooses Start. Handle repeated Start/Stop and failed builds. Use current dashboard Compose and local override, retaining its existing database volume.
